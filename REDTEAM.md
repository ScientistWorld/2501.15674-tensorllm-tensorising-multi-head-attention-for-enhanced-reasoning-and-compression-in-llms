# Gym scoring audit

**The gym does not reliably reward scientific contribution.** Removing the key idea scores lower, but the better-side check remains unestablished: more HOOI iterations improve weight reconstruction while worsening FEVER accuracy, and a broader search selected using only visible examples also worsens test accuracy. These are attempted improvements, not evidence of a genuinely better reasoning method. Meanwhile, several shortcuts strictly beat the reference under every positive finite metric normalization, and an entirely unsuccessful method can tie by omitting its score key.

## Genuine variants and quality ordering

All numbers below come from the unchanged, no-argument hidden test. Accuracy, balanced accuracy and distribution shift are percentages. The anchor is the gym's original `scoring/scores_test.json`, snapshotted in [original_scores_test.json](eval/test/history/state/original_scores_test.json); paper targets in `reference.json` are not substituted for that anchor.

The reference uses layer 6, ranks (384,48,4), five HOOI iterations. Twenty iterations reduce relative reconstruction error from 0.5789508 to 0.5787871, but lose 3.125 accuracy points. The broader search exhausts nine layers × eight rank tuples, with ten iterations, selecting by even-row accuracy and then even-row NLL. It selects layer 6, ranks (416,48,4); [selection and all 72 trials](eval/test/history/better_visible_search/search_progress.json) are saved. Its improved reconstruction error, 0.5625365, likewise does not improve reasoning. The rank correctly penalizes these observed task regressions; improving the reconstruction objective is not necessarily improving the paper's reasoning objective. Neither run establishes the requested better-method positive control.

Both weaker variants score below the reference by much more than the measured seed spread. The dense baseline is near chance and clearly below the reference. No scored metric is already at its favorable bound for valid outputs: accuracy and balanced accuracy are below 100; NLL and distribution shift are above zero; compression has no enforced finite upper bound. The evaluator does not enforce NLL's legitimate lower bound of zero. There is numerical room for genuine gains, but task validity is not protected.

## Seeds, reproduction and problem fidelity

Seeds [0](eval/test/history/reference_seed0/scores_test.json), [1](eval/test/history/reference_seed1/scores_test.json), [2](eval/test/history/reference_seed2/scores_test.json) all produce exactly the same five test metrics: **56.875, 57.301438399, 0.698506673425, 18.125, 1.994778209169**. The max-minus-min spread is **zero for every metric and for rank**. Each rerun recomputes the proposed decomposition and inference; only the unchanged original-model baseline predictions are reused for seeds 1 and 2. This implementation uses deterministic SVD, deterministic inference and no stochastic training, so changing the seed has no effect. The reruns differ from the original gym anchor only by 0.000001953 NLL, consistent with numerical/runtime differences rather than contribution. Zero seed spread does not measure uncertainty from selecting a small dataset.

**The reproduced method does beat its dense baseline in the paper's reported direction:** 56.875 versus 51.250 accuracy, lower NLL, and component compression 1.9948 versus 1. Table II of the [local paper](paper/2501.15674.md) reports RoBERTa FEVER accuracy 50.45 versus 50.00, loss 1.47 versus 2.50, compression 3.74. The gym reproduces the direction on this subset, not those magnitudes or an independent generalization result.

The shared Tucker procedure is identifiable in the implementation: tensorization of Q/K/V/O, shared factors on the three non-head modes, an uncompressed head mode, HOSVD initialization and HOOI, followed by reconstruction of one attention layer. Departures from the paper/settings are:

- Only RoBERTa/FEVER is reproduced, rather than three model families and four tasks; LASER comparisons, hybrids and secondary ablations are absent.
- Data are 320 real FEVER support/refute claims, the first 160 per class from `shared_task_dev.jsonl`. The preparation code does not perform the paper's conflicting-claim filter. This is a scaled subset, not synthetic data.
- Test is the odd-indexed half of supplied prediction rows, 160 cases, rather than the paper's last 20%. Crucially, the original reproduction chooses `tensorllm_best` using accuracy/loss over **all** supplied rows before this split. Its reference selection has therefore already used the future hidden examples.
- The prompt uses one mask and a trailing period instead of the paper's five appended masks. Input length is capped at 192 tokens. Gym NLL explicitly normalizes over true/false; the paper describes ground-truth-token NLL without specifying this binary renormalization, so the losses are not established as directly comparable.
- Decomposition is custom PyTorch rather than TensorLy, with an explicit limited rank/layer grid and five HOOI updates for the reference. The selected compression is 1.99 rather than the paper's 3.74.
- Factors are counted but not saved as a deployed compressed model; inference uses reconstructed dense weights. Thus compression is a theoretical representation count, not demonstrated storage, memory or latency reduction.

The subset is not saturated and shows a directional denoising effect, but does **not** establish that improvement here transfers to the paper's problem: selection contamination, changed prompting/loss and 160 test examples prevent that inference. One answer changes test accuracy by 0.625 percentage points, larger than the paper's 0.45-point RoBERTa FEVER gain. The honest visible-only search losing to the contaminated reference reinforces this limitation.

## Shortcut results

Every row has an executable `eval/test/history/<name>/run.sh`, retained input artifacts, evaluator logs, exit status and, when written, exact scores in that folder. Links below go to those runners. **R** means the seed-0 reference metric vector above. Unmentioned metrics remain R. A tie is explicitly treated as a shortcut, including cached predictions that let the evaluator ignore a destroyed model.

The reported Δ values are illustrative ranks using the finite successful audit cohort, plus the original reference. Exact future rank values cannot be known because normalization depends on the future attempts. The formula used is

`Δ = Δaccuracy/σaccuracy + 0.5·Δbalanced_accuracy/σbalanced_accuracy − 0.25·Δloss/σloss − 0.2·Δshift/σshift + 0.25·Δcompression/σcompression`.

The experiment weight is 1. Coefficients are absolute magnitudes; in particular the negative coefficient stored for shift does not reverse its lower-is-better direction. Each σ is a population standard deviation across that cohort. The audit-cohort σ values, cohort membership and all contributions are in [summary.json](eval/test/history/summary.json); the two cohorts intentionally show that units do not determine a metric's weight. A componentwise strict improvement beats R for any positive finite σ. Missing values contribute nothing under the specified rank; NaN handling and failed-job admission are not specified, so neither is invented here.

The exhaustive answer shortcut solves the actual test, but its oracle is leaked gold, not a label-free scientific solver. This demonstrates trivial answer enumeration/lookup, not feasibility of enumerating all `2^160` joint predictions without feedback. The exhaustive 72-condition compression search does not solve FEVER. Tucker decomposition has no obvious finite candidate enumeration that independently supplies factual answers; no stronger claim that intrinsic tensor compression is computationally too small is supported by these runs.

## Structural findings and scope

The primary scored benefit and compression constraint are both present on successful selected methods, but neither is independently anchored. The evaluator trusts submitted labels and row order/count, submitted NLL, and submitted parameter counts. It never checks predictions against fixed claims/gold or a compressed model. Baseline/reference files were not needed to construct the paying shortcuts. Moving ground truth, test size, or the fixed-model artifact suffices.

The additive rank does **not** prevent task failure from outranking the reference. The alternating-label shortcut is below chance on this test yet wins by improving distribution matching/loss and inventing compression; normalization limits units, not compensation. Genuine rank-one compression alone did not win. For a stronger, normalization-independent failure, forged labels let a constant predictor dominate every benefit metric while maintaining CR. Distribution matching is not evidence of correct reasoning.

Failure completeness also fails. Empty/null artifacts raise before any output is written, rather than assigning every scored metric its worst value. A stale score file remains untouched. A successful missing-key shortcut is independently proven: test's requested keys come from agent-writable `scoring/scores_train.json` (or mutable `scores.json` fallback), so excluding an unsuccessful method yields no loss. An additional on-disk manifest method is silently skipped. Successful selected methods do emit all five metrics; coverage of every method and failed run is absent.

The single bundled CPU job, **28d67135-6c2**, completed with exit 0 after about 84 minutes. [Job evidence](eval/test/history/job_evidence.json) records its timings and log hashes. [bundle.sh](eval/test/history/bundle.sh) reproduces the runs; [summary.tsv](eval/test/history/summary.tsv) lists raw metric vectors and local ranks. Runs use the improve-mode view, including the public method implementation. Each scenario installs artifacts at the default path, invokes visible evaluation, then launches **`bash scripts/evaluate_test.sh` with no arguments** as a separate process inside the job container. Scenarios share the job's container, rather than getting a new container each; they leave no worker process behind, and every demonstrated shortcut uses persistent files only. Evaluators and Python environment were unchanged. Score JSON files unavailable to future scientists were hidden during each scenario; own reference rerun predictions were reused to save computation. Paper/hidden reference files were used only for audit comparison, never for shortcut construction or genuine variant selection. Model config, scoring JSON and the default manifest were restored after each run.

For the next iteration, the highest-value fixes are independent gold/ID/count validation, independently computed probabilities and model-size evidence, evaluator-owned method discovery and failure-to-worst handling, an independent reference selection/test split, and a score rule that cannot trade away the task requirement. These changes are recommendations only; this audit leaves the gym unchanged outside its report, `eval/test/history/`, and the required completion signal.

Restoration used git commit `e35b7b1f65dd14a167687a2491627f915e339e53`. All mutable gym files, including `scripts/run.sh`, match that commit. The platform supplies `README.md` and `manifest.json` as mounted null devices and `trajectory/` as read-only; their pre-existing worktree differences could not be restored by git and were not altered by the audit.
